# 目录与规则流水线

主分支不继承旧流水线“用泛关键词发现页面，再反向拼目录”的结果。改造前产物只保存在 `backup` 分支。

## 数据顺序

1. 从公开可访问的国内主流漫画平台分类页只整理作品名称，并按分类汇总；第一步参数文档不写详情链接、封面或章节。
2. 每个语种、每个分类生成一份作品参数文档：`parameters/catalog/<language>/<category>.json`。
3. 整理标题并去重。章节后缀（如“第1话”“第一集”“最新章节”）从书名移除；第一季、第二季、前传、外传、番外、重制版等作品限定词必须保留并视为不同作品。
4. 第二步为每个分类只维护一份搜索状态文件和一份汇总结果文件。每轮跳过已标记作品，只搜索未标记作品；目录再长也可跨运行续接。
5. 逐个作品使用规范名和别名进行全网搜索。搜索结果只是候选，不能直接发布。
6. 对每个候选执行同一作品身份验证，并取得真实章节目录。
7. 抽查首章、中间章、最新章；三章都必须达到 `config/pipeline.json` 的最小正文图片数。`readability-v5` 明确排除缩略图条、封面、推荐图和页面装饰，并要求三章正文集合显著不同。
8. 在通过实读验证的候选中选择章节数最多者。并列时按抽样正文图片总数排序，再按稳定 URL 排序，保证结果可重复。
9. 将胜出来源写入作品来源表，并同步累计到按语种区分的域名台账。
10. 任一作品完成来源和域名规则验证后即可增量进入 App 在线目录，不等待整个长目录；同一批次没有新增、移除或修正可用作品时不提升线上版本。
11. 所有分类的全部作品都标记为已搜索后，才算一轮完成；此时统一重置搜索标记，保留汇总结果供下一轮有效性复检。
12. 域名分析器使用该域名下多部已验证作品推导站点级选择器。每个域名、每个兼容页面结构只能生成一条规则。
13. 新规则必须回放该域名台账里的全部样本；任何作品失败，该规则不得发布。
14. 只有拥有胜出来源、域名规则回放通过的作品才能进入 App 目录。

## 硬门禁

- 不允许使用首页、分类页、排行页作为作品详情页。
- 搜索词、候选标题、详情标题必须指向同一作品。
- 不允许把推荐作品、导航项或其他作品章节混入目录。
- 封面不计入正文图片，Logo、头像、横幅、占位图和推荐图不计入正文。
- 域名分析推断出的精确正文图片 CSS 选择器必须编译进 App 规则；禁止在发布阶段重新退化为匹配页面全部 `<img>`/图片 URL 的通用正则。
- 域名账本按“域名 + 作品 ID”去重，同一本作品不能重复增加域名回放证明数量。
- 章节数必须来自去重后的作品章节 URL，不能使用页面链接总数。
- 不允许以渲染兜底、登录、付费、验证码或反爬绕过作为“可读”证据。
- `zh-Hans` 目录只接受简体中文作品参数，不从其他语种补足数量。
- 数量不足时明确报告缺口，不得用未验证项目填满每类目标数。

## 中间产物

- 原始平台观察：`observations/platform/<language>/*.jsonl`
- 分类参数：`parameters/catalog/<language>/<category>.json`
- 分类搜索状态：`state/search/<language>/<category>.json`
- 分类候选汇总：`generated/v3/audits/<category>.jsonl`
- 分类最佳来源：`generated/v3/best/<category>.json`
- 全局最佳来源：`generated/v3/best_sources.<language>.json`
- 域名台账：`generated/v3/domain_ledger.<language>.json`
- 站点规则：`rules/index.<language>.json`
- 最终目录：`catalog/catalog.<language>.json`

只有通过全部门禁的新目录才能更新 App 的线上清单地址。

每个阶段缺少上游证据时都会退出失败，不创建凑数目录。联网采集器和逐书审计器按“平台/语种/分类/作品 ID”保存检查点。
